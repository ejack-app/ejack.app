## 🧾 نموذج موافقات الأذونات

Google Play يسألك عن سبب كل إذن حسّاس. استخدم هذه الصياغة:

### الموقع (Location)
```
نستخدم موقعك لتوجيه الطلبات بين السائقين والعملاء، وتتبع الرحلة النشطة فقط
أثناء التوصيل. لا نشارك موقعك مع أطراف خارجية. يمكنك إيقاف التتبع من داخل
التطبيق.
```

### الكاميرا (Camera)
```
نستخدم الكاميرا لتصوير مستندات التسليم (الفاتورة الموقّعة، صورة البضاعة) عند
انتهاء الرحلة. الصور لا تُرفع إلا بموافقتك الصريحة.
```

### الإشعارات (POST_NOTIFICATIONS)
```
نرسل لك إشعارات عند تحديث حالة طلبك (استُلم، في الطريق، تم التسليم) أو عند
إسناد رحلة جديدة لك إذا كنت سائقاً. يمكنك إيقافها من إعدادات الهاتف.
```

## 🚀 خطة الإصدار المرحلي

### المرحلة 1: اختبار داخلي (Internal Testing)
- **المدة:** يومان
- **عدد المختبرين:** 5-10 (فريقك)
- **الهدف:** تأكد من عدم وجود crashes

### المرحلة 2: اختبار مغلق (Closed Testing / Alpha)
- **المدة:** أسبوع
- **عدد المختبرين:** 20-50 (سائقين وعملاء مختارين)
- **الهدف:** جمع تعليقات عن الواجهة والأداء

### المرحلة 3: اختبار مفتوح (Open Testing / Beta)
- **المدة:** أسبوعين
- **المختبرون:** أي شخص يحمل الرابط
- **الهدف:** قياس الأداء على أجهزة متنوعة

### المرحلة 4: الإنتاج (Production)
- طرح تدريجي: 10% → 25% → 50% → 100%
- راقب Firebase Crashlytics في كل مرحلة

## 📊 نصائح للترتيب في البحث (ASO)

1. **ضع الكلمة المفتاحية في اسم التطبيق** (مثل "Ejack - توصيل")
2. **احصل على 50+ تقييم** في أول شهر → ترتيب أعلى
3. **رد على تقييمات المستخدمين** → ينسب Google الاهتمام
4. **حدّث التطبيق كل 4-6 أسابيع** → خوارزمية Play تفضّله
5. **صورة الميزة الجيدة** ترفع نسبة التحويل 15-30%
